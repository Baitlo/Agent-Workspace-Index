## الاستخدام

```bash
# الذاكرة المنسقة والملخصات فقط.
awi --index-dir /tmp/my-awi-index memory \
  --project-root /absolute/path/to/workspace

# تضمين سجل الدردشة/الجلسة الخام المطابق بشكل صريح.
awi --index-dir /tmp/my-awi-index memory \
  --project-root /absolute/path/to/workspace \
  --include-raw

# البحث فقط في الذاكرة المرتبطة بالمشروع الحالي.
awi --index-dir /tmp/my-awi-index search "previous deployment decision" \
  --kind agent_memory \
  --context-path /absolute/path/to/workspace \
  --json
```

يقوم المثبت بتشغيل النموذج المنسق افتراضيًا. استخدم `--skip-agent-memory` لتعطيله أو `--include-raw-memory` للاختيار في السجل الخام.

## المصادر

يقتصر الاكتشاف على المشروع القانوني المحدد:

| الوكيل | المصادر المنسقة الافتراضية | الاشتراك الخام |
|---|---|---|
| Trae | ملف تعريف المستخدم، ذاكرة المشروع المطابقة، ملخصات المواضيع، ملخصات الجلسات | لا شيء يتجاوز تلك الملخصات |
| Codex | `MEMORY.md`، `memory_summary.md`، ملخصات النشر المطابقة | JSONL النشر الخام المرتبط و `raw_memories.md` |
| Zcode | جذر الذاكرة المعين للمشروع بواسطة بيانات تعريف وقت تشغيل Zcode | ملفات النشر/الوكيل المطابقة |
| Gemini CLI | لا شيء | سجل المشروع المعين ودلائل الدردشة |
| Claude Code | دليل ذاكرة المشروع المطابق | ملفات الجلسة التي تحدد المشروع |

يتم استبعاد دلائل جلسات Argos/SRE عمدًا لأنها تتطلب سير عمل تشخيص Argos بدلاً من فهرسة الملفات بالجملة. لا يقوم AWI أبدًا بمسح دليل home بالكامل.

## البيانات الوصفية والتصنيف

تتضمن كل نتيجة ذاكرة:

- الوكيل المصدر؛
- الطبقة: `user_profile`، `project_summary`، `topic_summary`، `session_summary`، `memory_note`، أو `raw_history`؛
- `name` و `description` YAML frontmatter الاختياريان؛
- جذر مساحة العمل القانوني ومفتاح مشروع المزود عند توفرهما؛
- معرف الجلسة عندما يمكن اشتقاقه؛
- وقت الملاحظة وعلامة السجل الخام.

عندما يتم توفير `context_path` أو مرشح جذر المشروع، يتم رفض الذاكرة من مشروع آخر. يتم تصنيف ذاكرة المشروع الدقيق قبل الذاكرة العامة. تتلقى مطابقات اسم الملف الدقيق و `name` frontmatter أقوى دفعة بيانات وصفية؛ يوفر تداخل الوصف دفعة أصغر. تعمل الاستعلامات على شكل معرف على تخفيض ملخصات `MEMORY.md`/المشروع الواسعة ما لم يتطابق الملخص نفسه تمامًا مع الكيان. يظل ترتيب الطبقات العادي دون تغيير للاستعلامات الواسعة، ويتم تصنيف الملخصات المنسقة قبل السجل الخام، والحداثة ليست سوى عامل حسم صغير. يتم طي النسخ ذات المحتوى المتطابق من وكلاء مختلفين بعد التصنيف. يتم تنشيط استرجاع الذاكرة بـ `--kind agent_memory`. تستخدم مستندات الذاكرة فهرس Tantivy مخصصًا بحيث لا يمكن لمفرداتها تغيير إحصائيات IDF أو تصنيف الشفرة/البيانات العادي.

## التحليل والأمان

يتم فهرسة ذاكرة Markdown كنص محدود. يتم تطبيع ذاكرة JSON/JSONL إلى حقول ذات صلة بالإنسان مثل النية والإجراءات والنتيجة والحقائق المكتسبة والدور والرسالة والمحتوى؛ يتم حذف معرفات النقل والبيانات الوصفية للملخص الداخلي من مستند البحث. لا يتم إرسال ذاكرة JSONL إلى تحليل DuckDB.

لا تزال فحوصات الحجم العادية و UTF-8 والتجاهل واسم الملف الحساس سارية. تجعل بيانات الاعتماد أو المفاتيح الخاصة عالية الثقة ملف الذاكرة بالكامل بيانات وصفية فقط. يتم تعطيل السجل الخام ما لم يُطلب صراحة، وتظل الملفات الخام كبيرة الحجم بيانات وصفية فقط ضمن حد المحتوى المكون.

يحتفظ `awi memory` بجذر المشروع القانوني وسياسة السجل الخام. تعيد كل دورة منتج اكتشاف مصادر الوكيل لهذا المشروع قبل النشر، لذا تظهر دلائل مشروع المزود الجديدة دون إعادة تثبيت AWI. يتم أيضًا مطابقة الجذور المسجلة مسبقًا عندما تختفي، مما يمنع بقاء الذاكرة المحذوفة قابلة للبحث. يتم تحديث JSONL الملحق الملحق في المطابقة الدورية التالية؛ لا تؤدي الملفات الخام الثقيلة الإلحاق إلى إعادة بناء لقطة لكل كتابة.

يعرض `awi status --json` كائن `memory` مع عدد المشاريع/المصادر المسجلة والملفات النشطة وأحدث جيل ذاكرة والتأخر النسبي للجيل و `stale_files`/`missing_files` لنظام الملفات والحد الأقصى لتأخر المصدر وعمر أقدم مصدر. تُعد أعداد الملفات القديمة والمفقودة في نظام الملفات إشارات النضارة الموثوقة؛ فالتأخر المنخفض للجيل وحده لا يثبت أن الذاكرة الخارجية محدثة.

## التحقق من التطوير

اكتشف تشغيل Bona معزول 35 جذرًا ذا صلة بالمشروع وفهرس 489 ملفًا منسقًا من Codex و Trae و Zcode بدون أخطاء استخراج؛ ظلت دردشات Gemini الخام مستبعدة. ظلت مجموعة استرجاع الشفرة/البيانات الحالية المكونة من 16 حالة مستقرة bit-لـ-bit عند Recall@10 `1.0` و MRR `0.6006` و nDCG@10 `0.6950` ومعدل القدم `0`. كان P95 لبناء الإصدار `24.06 مللي ثانية`. لا تزال هذه المجموعة `candidate_pending_dual_review`، وليست بوابة إصدار مجمدة. لا تبلغ عن الدقة/الاستدعاء الرسمي أو Inspect@K أو MRR حتى يقوم مراجعان مختلفان بتسمية مجموعة الاستعلامات بشكل مستقل ويحكمان الخلافات.
