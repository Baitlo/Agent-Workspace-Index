# การสร้างดัชนีความรู้ของเอเจนต์

[English](agent-knowledge.md) · [中文](agent-knowledge.zh.md) · [繁體中文](agent-knowledge.zh-TW.md) · [日本語](agent-knowledge.ja.md) · [한국어](agent-knowledge.ko.md) · [Русский](agent-knowledge.ru.md) · [Français](agent-knowledge.fr.md) · [Deutsch](agent-knowledge.de.md) · [Português](agent-knowledge.pt.md) · [Español](agent-knowledge.es.md) · [العربية](agent-knowledge.ar.md) · [Italiano](agent-knowledge.it.md) · [Ελληνικά](agent-knowledge.el.md) · **ไทย** · [Bahasa Melayu](agent-knowledge.ms.md)

ประวัติโครงการข้ามเอเจนต์ได้รับการจัดการแยกต่างหากเป็น `agent_memory` ดู [การสร้างดัชนีหน่วยความจำข้ามเอเจนต์](agent-memory.md)

## ประเภทเอกสาร

| ไฟล์ | ประเภท AWI | เมทาดาทาที่มีโครงสร้าง |
|---|---|---|
| `AGENTS.md` | `agent_instructions` | ไดเรกทอรีขอบเขต ความลึกของลำดับความสำคัญ หัวข้อ การอ้างอิงในเครื่อง |
| `SKILL.md` | `agent_skill` | `name` และ `description` YAML หัวข้อ การอ้างอิงในเครื่อง |

ข้อความ Markdown ที่ถูกจำกัดทั้งหมดยังคงค้นหาได้ `workspace_inspect` ส่งคืนเมทาดาทาที่มีโครงสร้างพร้อมกับเมทาดาทาไฟล์ปกติและข้อความที่ตัดมา

## การค้นพบ

การปรับปรุงพื้นที่ทำงานปกติจะสร้างดัชนีไฟล์ `AGENTS.md` และ `SKILL.md` ภายใต้พื้นที่ทำงานนั้น โดยอยู่ภายใต้ `.gitignore` `.awiignore` และการยกเว้นเริ่มต้นของ AWI

โปรแกรมติดตั้งครั้งแรกจะค้นพบเพิ่มเติม:

- ไฟล์ `AGENTS.md` ในไดเรกทอรีบรรพบุรุษเหนือพื้นที่ทำงานที่เลือก
- แมนิเฟสต์ `SKILL.md` ภายใต้ไดเรกทอรีโครงการและผู้ใช้ที่รู้จักสำหรับไคลเอนต์เอเจนต์ที่รองรับ

เอกสารภายนอกแต่ละฉบับได้รับการลงทะเบียนเป็นรูทไฟล์เดียว AWI ไม่สร้างดัชนีไดเรกทอรีบ้านทั้งหมดหรือเนื้อหาทั้งหมดของแพ็กเกจ Skill สากล `--skip-agent-knowledge` ปิดใช้งานการค้นพบเพิ่มเติมนี้

ลิงก์ Markdown ในเครื่องจากเอกสารเอเจนต์จะถูกบันทึกเมื่อเป้าหมายของพวกมันมีอยู่และยังคงอยู่ภายในรูทเอกสารเท่านั้น ไฟล์ที่อ้างถึงสามารถค้นหาได้เมื่อถูกครอบคลุมโดยรูทพื้นที่ทำงานแล้ว มิฉะนั้นเส้นทางอ้างอิงจะถูกส่งคืนเป็นเมทาดาทาสำหรับการตรวจสอบอย่างชัดแจ้งด้วยเครื่องมือไฟล์อื่น

## ขอบเขตและการจัดอันดับ

ส่ง `context_path` ไปยัง `workspace_search` เมื่อแก้ไขคำสั่งที่เก็บ:

```bash
awi search "build and test rules" \
  --kind agent_instructions \
  --context-path /workspace/service/src/main.rs \
  --json
```

AWI ไม่รวมไฟล์ `AGENTS.md` ที่ขอบเขตไม่ใช่บรรพบุรุษของเส้นทางบริบท ไฟล์ที่ใช้บังคับได้รับการจัดอันดับตามความลึกของขอบเขตดังนั้นคำสั่งที่ใกล้ที่สุดจะมาก่อน หลังจากการจัดอันดับนี้เอกสารเอเจนต์ที่มีเนื้อหาเหมือนกันจะถูกยุบ ซึ่งจะระงับการทำซ้ำของ Skill และ worktree ที่คัดลอกโดยไม่สูญเสียคำสั่งที่ใช้บังคับได้ที่ใกล้ที่สุด

เมื่อไม่ระบุตัวกรองชนิด คำสั่ง Agent และ Skills จะถูกค้นหาร่วมกับโค้ดและข้อมูล ใช้ `--kind agent_skill` หรือ `--kind agent_instructions` เฉพาะเมื่อต้องการจำกัดผลลัพธ์ไว้ที่เอกสาร Agent ชนิดเดียว การส่ง `context_path` จะใช้การกรองและจัดอันดับตามขอบเขตของคำสั่ง

## ความปลอดภัย

เอกสารเอเจนต์ยังคงอยู่ภายใต้การตรวจสอบขนาดปกติ UTF-8 ลิงก์สัญลักษณ์และชื่อไฟล์ที่ละเอียดอ่อน รูปแบบคีย์ส่วนตัวและโทเค็นผู้ให้บริการที่มีความมั่นใจสูงในเนื้อหาของพวกมันทำให้เกิดผลลัพธ์เฉพาะเมทาดาทาด้วย `metadata_only_sensitive_content` เนื้อหา การแสดงตัวอย่าง และเมทาดาทาเอเจนต์ที่แยกวิเคราะห์จะไม่ถูกจัดเก็บ

Frontmatter Skill ที่ผิดรูปแบบจะถูกบันทึกเป็นความล้มเหลวในการดึงข้อมูล ในขณะที่เนื้อหา Markdown ใหม่ยังคงแทนที่ข้อความที่สร้างดัชนีเก่ากว่า สิ่งนี้หลีกเลี่ยงการให้บริการเนื้อหาที่ล้าสมัยเมื่อเฉพาะการแยกวิเคราะห์เมทาดาทาที่มีโครงสร้างล้มเหลว

## การตรวจสอบการพัฒนา

การติดตั้งแบบแยกส่วนบนสภาพแวดล้อม Bona ปัจจุบันค้นพบเอกสารเอเจนต์ที่เป็นมาตรฐาน 136 ฉบับโดยไม่มีความล้มเหลวในการดึงข้อมูล คิวรีควันที่มุ่งเป้าหมายเลือก `wukong-dag-failure-debugger` ก่อนสำหรับคิวรีความล้มเหลว Wukong DAG/LogID และ `AGENTS.md` ของ Bona สำหรับบริบทแหล่งที่มาของ AWI

ในชุดการดึงข้อมูลการพัฒนา 16 กรณีที่มีอยู่ การเพิ่มเอกสารเอเจนต์เหล่านี้รักษา Recall@10 ไว้ที่ `1.0` และอัตราผลลัพธ์ที่ล้าสมัยที่ `0` MRR เปลี่ยนจาก `0.5975` เป็น `0.6027` nDCG@10 จาก `0.6922` เป็น `0.6969` และ P95 ของบิลด์รีลีสจาก `8.07 ms` เป็น `25.88 ms` ความหน่วงยังคงต่ำกว่าเป้าหมายการค้นหาแบบไฮบริด `150 ms` ชุดการพัฒนานี้ยังคงรอการทบทวนสองครั้งและไม่ใช่เกณฑ์มาตรฐานรีลีสที่ตรึงไว้
