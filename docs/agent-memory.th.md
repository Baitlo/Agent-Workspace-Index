## การใช้งาน

```bash
# เฉพาะหน่วยความจำและบทสรุปที่คัดสรร
awi --index-dir /tmp/my-awi-index memory \
  --project-root /absolute/path/to/workspace

# รวมประวัติแชท/เซสชันดิบที่ตรงกันอย่างชัดแจ้ง
awi --index-dir /tmp/my-awi-index memory \
  --project-root /absolute/path/to/workspace \
  --include-raw

# ค้นหาเฉพาะหน่วยความจำที่เกี่ยวข้องกับโครงการปัจจุบัน
awi --index-dir /tmp/my-awi-index search "previous deployment decision" \
  --kind agent_memory \
  --context-path /absolute/path/to/workspace \
  --json
```

โปรแกรมติดตั้งเรียกใช้แบบฟอร์มที่คัดสรรโดยค่าเริ่มต้น ใช้ `--skip-agent-memory` เพื่อปิดใช้งานหรือ `--include-raw-memory` เพื่อเลือกเข้าร่วมประวัติดิบ

## แหล่งที่มา

การค้นพบถูกจำกัดเฉพาะโครงการมาตรฐานที่เลือก:

| เอเจนต์ | แหล่งที่คัดสรรเริ่มต้น | การเลือกเข้าร่วมดิบ |
|---|---|---|
| Trae | โปรไฟล์ผู้ใช้ หน่วยความจำโครงการที่ตรงกัน บทสรุปหัวข้อ บทสรุปเซสชัน | ไม่มีอะไรเกินกว่าบทสรุปเหล่านั้น |
| Codex | `MEMORY.md` `memory_summary.md` บทสรุปการเปิดตัวที่ตรงกัน | JSONL การเปิดตัวดิบที่เชื่อมโยงและ `raw_memories.md` |
| Zcode | รูทหน่วยความจำที่แมปกับโครงการโดยเมทาดาทารันไทม์ Zcode | ไฟล์การเปิดตัว/เอเจนต์ที่ตรงกัน |
| Gemini CLI | ไม่มี | ประวัติโครงการที่แมปและไดเรกทอรีแชท |
| Claude Code | ไดเรกทอรีหน่วยความจำโครงการที่ตรงกัน | ไฟล์เซสชันที่ระบุโครงการ |

ไดเรกทอรีเซสชัน Argos/SRE ถูกแยกออกโดยเจตนาเนื่องจากต้องใช้เวิร์กโฟลว์การวินิจฉัย Argos แทนการสร้างดัชนีไฟล์จำนวนมาก AWI ไม่สแกนไดเรกทอรีบ้านทั้งหมด

## เมทาดาทาและการจัดอันดับ

ทุกผลลัพธ์หน่วยความจำประกอบด้วย:

- เอเจนต์ต้นทาง;
- ชั้น: `user_profile`, `project_summary`, `topic_summary`, `session_summary`, `memory_note` หรือ `raw_history`;
- `name` และ `description` YAML frontmatter ที่เป็นทางเลือก;
- รูทพื้นที่ทำงานมาตรฐานและคีย์โครงการของผู้ให้บริการเมื่อมี;
- ID เซสชันเมื่อสามารถสืบทอดได้;
- เวลาสังเกตและแฟล็กประวัติดิบ

เมื่อมีการให้ `context_path` หรือตัวกรองรูทโครงการ หน่วยความจำจากโครงการอื่นจะถูกปฏิเสธ หน่วยความจำโครงการที่แน่นอนจะถูกจัดอันดับก่อนหน่วยความจำสากล การจับคู่ชื่อไฟล์ที่แน่นอนและ `name` frontmatter ได้รับการเพิ่มเมทาดาทาที่แข็งแกร่งที่สุด การทับซ้อนของคำอธิบายให้การเพิ่มที่น้อยกว่า คิวรีรูปร่างตัวระบุจะลดระดับบทสรุป `MEMORY.md`/โครงการแบบกว้าง เว้นแต่บทสรุปนั้นจะตรงกับเอนทิตีอย่างแน่นอน ลำดับชั้นปกติยังคงไม่เปลี่ยนแปลงสำหรับคิวรีแบบกว้าง บทสรุปที่คัดสรรจะถูกจัดอันดับก่อนประวัติดิบ และความใหม่เป็นเพียงตัวตัดสินเล็กน้อย สำเนาที่มีเนื้อหาเหมือนกันจากเอเจนต์ที่แตกต่างกันจะถูกยุบหลังจากการจัดอันดับ การดึงหน่วยความจำถูกเปิดใช้งานด้วย `--kind agent_memory` เอกสารหน่วยความจำใช้ดัชนี Tantivy เฉพาะดังนั้นคำศัพท์ของพวกมันจึงไม่สามารถเปลี่ยนแปลงสถิติ IDF หรือการจัดอันดับโค้ด/ข้อมูลทั่วไปได้

## การแยกวิเคราะห์และความปลอดภัย

หน่วยความจำ Markdown ถูกสร้างดัชนีเป็นข้อความที่ถูกจำกัด หน่วยความจำ JSON/JSONL ถูกทำให้เป็นมาตรฐานเป็นฟิลด์ที่เกี่ยวข้องกับมนุษย์ เช่น เจตนา การกระทำ ผลลัพธ์ ข้อเท็จจริงที่เรียนรู้ บทบาท ข้อความ และเนื้อหา ID การขนส่งและเมทาดาทาบทสรุปภายในถูกละเว้นจากเอกสารค้นหา หน่วยความจำ JSONL ไม่ถูกส่งไปยังการทำโปรไฟล์ DuckDB

การตรวจสอบขนาดปกติ UTF-8 การละเว้น และชื่อไฟล์ที่ละเอียดอ่อนยังคงใช้ได้ ข้อมูลประจำตัวหรือคีย์ส่วนตัวที่มีความมั่นใจสูงทำให้ไฟล์หน่วยความจำทั้งหมดเป็นเฉพาะเมทาดาทา ประวัติดิบถูกปิดใช้งานเว้นแต่จะร้องขออย่างชัดแจ้ง และไฟล์ดิบขนาดใหญ่ยังคงเป็นเฉพาะเมทาดาทาภายใต้ขีดจำกัดเนื้อหาที่กำหนดค่า

`awi memory` คงรูทโครงการมาตรฐานและนโยบายประวัติดิบ ทุกรอบของผู้ผลิตจะค้นพบแหล่งเอเจนต์ของโครงการนั้นอีกครั้งก่อนเผยแพร่ ดังนั้นไดเรกทอรีโครงการของผู้ให้บริการใหม่จึงปรากฏโดยไม่ต้องติดตั้ง AWI ใหม่ รูทที่ลงทะเบียนไว้ก่อนหน้านี้จะถูกปรับปรุงเมื่อหายไป ป้องกันไม่ให้หน่วยความจำที่ถูกลบยังคงค้นหาได้ JSONL บทสรุปที่ผนวกเข้ามาจะได้รับการรีเฟรชในการปรับปรุงเป็นระยะครั้งต่อไป ไฟล์ดิบที่มีการผนวกหนักไม่ทริกเกอร์การสร้างสแน็ปชอตใหม่ต่อการเขียน

`awi status --json` เปิดเผยวัตถุ `memory` พร้อมจำนวนโครงการ/แหล่งที่ลงทะเบียน ไฟล์ที่ใช้งานอยู่ รุ่นหน่วยความจำล่าสุดและความล่าช้าของรุ่นสัมพัทธ์ `stale_files`/`missing_files` ของระบบไฟล์ ความล่าช้าสูงสุดของแหล่ง และอายุของแหล่งที่เก่าแก่ที่สุด จำนวนไฟล์ที่ล้าสมัยและหายไปของระบบไฟล์เป็นสัญญาณความสดใหม่ที่เชื่อถือได้ ความล่าช้าของรุ่นที่ต่ำเพียงอย่างเดียวไม่พิสูจน์ว่าหน่วยความจำภายนอกทันสมัย

## การตรวจสอบการพัฒนา

การรัน Bona แบบแยกส่วนค้นพบ 35 รูทที่เกี่ยวข้องกับโครงการและสร้างดัชนีไฟล์ที่คัดสรร 489 ไฟล์จาก Codex, Trae และ Zcode โดยไม่มีความล้มเหลวในการดึงข้อมูล แชทดิบของ Gemini ยังคงถูกแยกออก ชุดการดึงข้อมูลโค้ด/ข้อมูล 16 กรณีที่มีอยู่ยังคงเสถียร bit-ต่อ-bit ที่ Recall@10 `1.0` MRR `0.6006` nDCG@10 `0.6950` และอัตราล้าสมัย `0` P95 ของบิลด์รีลีสอยู่ที่ `24.06 ms` ชุดนี้ยังคงเป็น `candidate_pending_dual_review` ไม่ใช่เกตรีลีสที่ตรึงไว้ อย่ารายงานความแม่นยำ/การเรียกคืนอย่างเป็นทางการ Inspect@K หรือ MRR จนกว่าผู้ตรวจสอบสองคนที่แตกต่างกันจะติดป้ายชุดคิวรีอย่างอิสระและตัดสินข้อขัดแย้ง
