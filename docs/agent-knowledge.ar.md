يتم التعامل مع سجل المشروع عبر الوكلاء بشكل منفصل كـ `agent_memory`؛ راجع [فهرسة ذاكرة الوكيل المتقاطع](agent-memory.md).

## أنواع المستندات

| الملف | نوع AWI | البيانات الوصفية المهيكلة |
|---|---|---|
| `AGENTS.md` | `agent_instructions` | دليل النطاق، عمق الأولوية، العناوين، المراجع المحلية |
| `SKILL.md` | `agent_skill` | `name` و `description` YAML، العناوين، المراجع المحلية |

يظل نص Markdown الكامل المحدود قابلاً للبحث. يعيد `workspace_inspect` البيانات الوصفية المهيكلة مع البيانات الوصفية العادية للملف ومقتطف المحتوى.

## الاكتشاف

تقوم مطابقة مساحة العمل العادية بفهرسة ملفات `AGENTS.md` و `SKILL.md` تحت تلك المساحة، مع مراعاة `.gitignore` و `.awiignore` واستثناءات AWI الافتراضية.

يكتشف مثبت التشغيل الأول بالإضافة إلى ذلك:

- ملفات `AGENTS.md` في الدلائل الأصلية فوق مساحة العمل المحددة؛
- بيانات `SKILL.md` تحت دلائل المشروع والمستخدم المعروفة لعملاء الوكيل المدعومين.

يتم تسجيل كل مستند خارجي كجذر ملف واحد. لا يقوم AWI بفهرسة دليل home كامل أو المحتويات الكاملة لحزم Skill العامة. `--skip-agent-knowledge` يعطل هذا الاكتشاف الإضافي.

يتم تسجيل روابط Markdown المحلية من مستند الوكيل فقط عندما يكون هدفها موجودًا ويظل داخل جذر المستند. تكون الملفات المرجعية قابلة للبحث عندما تكون مغطاة بالفعل بجذر مساحة عمل؛ وإلا يتم إرجاع مسار المرجع كبيانات وصفية للفحص الصريح باستخدام أداة ملف أخرى.

## النطاق والتصنيف

مرر `context_path` إلى `workspace_search` عند حل تعليمات المستودع:

```bash
awi search "build and test rules" \
  --kind agent_instructions \
  --context-path /workspace/service/src/main.rs \
  --json
```

يستبعد AWI ملفات `AGENTS.md` التي لا يكون نطاقها سلفًا لمسار السياق. يتم تصنيف الملفات القابلة للتطبيق حسب عمق النطاق بحيث تأتي التعليمات الأقرب أولاً. بعد هذا التصنيف، يتم طي مستندات الوكيل ذات المحتوى المتطابق، مما يقمع نسخ Skill و worktree المكررة دون فقدان التعليمات القابلة للتطبيق الأقرب.

عند عدم تحديد عامل تصفية للنوع، يتم البحث في تعليمات الوكيل وSkills إلى جانب الشفرة والبيانات. استخدم `--kind agent_skill` أو `--kind agent_instructions` فقط لحصر البحث في نوع واحد من مستندات الوكيل. يطبق `context_path` تصفية نطاق التعليمات وترتيبها.

## الأمان

تظل مستندات الوكيل خاضعة لفحوصات الحجم العادية و UTF-8 والرابط الرمزي واسم الملف الحساس. تؤدي أنماط المفتاح الخاص ورمز الموفر عالية الثقة في محتواها إلى نتيجة بيانات وصفية فقط مع `metadata_only_sensitive_content`؛ لا يتم تخزين المحتوى والمعاينة والبيانات الوصفية للوكيل المحللة.

يتم تسجيل frontmatter Skill المشوه كفشل استخراج، بينما لا يزال محتوى Markdown الجديد يحل محل أي نص مفهرس أقدم. هذا يتجنب تقديم محتوى قديم عندما يفشل فقط تحليل البيانات الوصفية المهيكلة.

## التحقق من التطوير

اكتشف تثبيت معزول على بيئة Bona الحالية 136 مستند وكيل قانوني بدون أخطاء استخراج. حددت استعلامات الدخان الموجهة `wukong-dag-failure-debugger` أولاً لاستعلام فشل Wukong DAG/LogID و `AGENTS.md` Bona لسياق مصدر AWI.

في مجموعة الاسترجاع التطويرية الحالية المكونة من 16 حالة، أدى إضافة مستندات الوكيل هذه إلى الحفاظ على Recall@10 عند `1.0` ومعدل النتائج القديمة عند `0`؛ تغير MRR من `0.5975` إلى `0.6027`، و nDCG@10 من `0.6922` إلى `0.6969`، و P95 لبناء الإصدار من `8.07 مللي ثانية` إلى `25.88 مللي ثانية`. يظل زمن الوصول أقل من هدف البحث الهجين `150 مللي ثانية`. تظل مجموعة التطوير هذه في انتظار المراجعة المزدوجة وليست معيار إصدار مجمدًا.
