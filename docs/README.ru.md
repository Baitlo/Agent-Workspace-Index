# AWI: Agent Workspace Index

[English](../README.md) · [中文](README.zh.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · **Русский** · [Français](README.fr.md) · [Deutsch](README.de.md) · [Português](README.pt.md) · [Español](README.es.md) · [العربية](README.ar.md) · [Italiano](README.it.md) · [Ελληνικά](README.el.md) · [ไทย](README.th.md) · [Bahasa Melayu](README.ms.md)

AWI — это локальный унифицированный индекс для кода, данных и операционных знаний агентов. Он индексирует исходный код, SQL, документы, журналы, JSON/JSONL, CSV/TSV, Parquet, `AGENTS.md`, навыки агентов и проектную межагентную память через единый ограниченный интерфейс CLI и Model Context Protocol (MCP).

Одна команда подключает этот индекс к 16 средам кодирования агентов, включая Codex, Claude Code, Gemini CLI, GitHub Copilot CLI, OpenCode, Qwen Code, Cline, Zed, Amazon Q Developer и Crush.

## Возможности

- Гибридный поиск Tantivy по путям, тексту, символам и схемам наборов данных.
- Извлечение символов Tree-sitter для Rust, Python и Go.
- Встроенные запросы DuckDB только для чтения по явно разрешённым файлам.
- Поиск `AGENTS.md` с учётом области и структурированные метаданные `SKILL.md`.
- Обнаружение проектной памяти в Trae, Codex, Zcode, Gemini и Claude.
- Проверки каталога SQLite, отклоняющие устаревшие результаты поиска.
- NFS-безопасные пути обновления `notify` и `reconcile`.
- Неизменяемые снимки поколений с атомарной активацией демона.
- Инструменты MCP: `workspace_search`, `workspace_inspect` и `workspace_query`.

Подробнее об обнаружении, области, ранжировании, дедупликации и семантике безопасности см. в разделе [Индексация знаний агентов](agent-knowledge.md). Об источниках памяти и границах необработанной истории см. в разделе [Индексация межагентной памяти](agent-memory.md).

## Готовые двоичные файлы для Linux и macOS

GitHub Releases предоставляет нативные двоичные файлы для:

- `x86_64-unknown-linux-gnu`
- `aarch64-unknown-linux-gnu`
- `aarch64-apple-darwin`
- `x86_64-apple-darwin`

Установите и настройте AWI для текущего репозитория одной командой:

```bash
curl -fsSL \
  https://raw.githubusercontent.com/Baitlo/Agent-Workspace-Index/main/scripts/install-release.sh |
  bash -s -- --workspace "$PWD"
```

Установщик определяет архитектуру Linux, загружает архив релиза и `SHA256SUMS`, проверяет контрольную сумму, устанавливает двоичный файл, обновляет управляемый раздел AWI в верхнем уровне `AGENTS.md` рабочей области, создаёт начальный индекс, обнаруживает знания агентов и курированную проектную память и регистрирует каждый обнаруженный поддерживаемый клиент агента. Существующее содержимое `AGENTS.md` сохраняется, а повторный запуск установщика заменяет, а не дублирует управляемый раздел.

Для сред, требующих проверки загруженного скрипта перед выполнением:

```bash
curl -fsSLO \
  https://raw.githubusercontent.com/Baitlo/Agent-Workspace-Index/main/scripts/install-release.sh
less install-release.sh
bash install-release.sh --workspace /absolute/path/to/your/repository
```

Опустите `--workspace`, чтобы установить только двоичный файл `awi`. Зафиксируйте релиз с помощью `--version v0.2.0`, выберите другое назначение с помощью `--bin-dir`, ограничьте клиентов с помощью `--clients` или отключите управляемый блок инструкций с помощью `--skip-agent-instructions`. Двоичные файлы Linux собираются нативно на раннерах Ubuntu 22.04, размещённых на GitHub, и требуют совместимых glibc и `libstdc++`. Двоичные файлы macOS собираются нативно на раннерах macOS 15 для Apple Silicon и Intel.

Семантический поиск остаётся необязательным. Дополнительно требуются Python, LanceDB, `llama-cpp-python` и совместимая модель встраивания GGUF. Сопровождающие должны следовать [чек-листу релиза](releasing.md).

## Установка с помощью агента

Предоставьте вашему агенту кодирования [рекомендуемый запрос на установку](agent-install-prompt.md) или запустите установщик из чекаута AWI:

```bash
bash scripts/install.sh --workspace /absolute/path/to/your/repository
```

Первый запуск собирает и устанавливает `awi`, обновляет управляемые инструкции AWI рабочей области, создаёт локальный индекс вне рабочей области, индексирует родительские файлы `AGENTS.md` и манифесты `SKILL.md`, найденные в разрешённых каталогах агентов, индексирует курированную память, связанную с этой рабочей областью, обнаруживает установленные клиенты агентов и регистрирует сервер AWI MCP у каждого поддерживаемого клиента. Операция идемпотентна. Передайте `--skip-agent-instructions`, `--skip-agent-knowledge` или `--skip-agent-memory`, чтобы отключить эти шаги. Необработанные чаты остаются исключёнными, если не указан `--include-raw-memory`. Rust и Cargo требуются только при сборке из исходного кода.

Если обнаружен Pi, установщик также устанавливает закреплённый `pi-mcp-adapter@2.36.0`, потому что Pi намеренно не имеет встроенного клиента MCP. Это сторонний пакет Pi; передайте `--skip-pi-adapter`, чтобы просмотреть или установить его отдельно, или установите `AWI_PI_MCP_ADAPTER_SPEC`, чтобы выбрать другую проверенную версию. Запустите `scripts/install.sh --help` для пользовательских параметров двоичного файла, индекса и клиента.

## Основное использование

```bash
# Создать или обновить индекс.
awi --index-dir /tmp/my-awi-index reconcile /path/to/workspace --json

# Запустить постоянный демон.
awi --index-dir /tmp/my-awi-index serve

# Поиск и проверка.
awi --index-dir /tmp/my-awi-index search "workspace query" --limit 10 --json
awi --index-dir /tmp/my-awi-index inspect /path/to/file --json
awi --index-dir /tmp/my-awi-index inspect /path/to/file \
  --symbol exact_function_name --json

# Разрешить инструкции, применимые к конкретному пути рабочей области.
awi --index-dir /tmp/my-awi-index search "build and test rules" \
  --kind agent_instructions --context-path /path/to/workspace/src/lib.rs --json

# Индексировать и искать автономный глобальный манифест навыка.
awi --index-dir /tmp/my-awi-index reconcile ~/.agents/skills/example/SKILL.md --json
awi --index-dir /tmp/my-awi-index search "diagnose deployment failures" \
  --kind agent_skill --json

# Обнаружить курированную память для этого проекта и искать её.
awi --index-dir /tmp/my-awi-index memory --project-root /path/to/workspace
awi --index-dir /tmp/my-awi-index search "previous rollout decision" \
  --kind agent_memory --context-path /path/to/workspace --json

# Запустить адаптер MCP stdio.
awi --index-dir /tmp/my-awi-index mcp

# Сохранять фактические вызовы инструментов MCP для последующего анализа поиска.
awi --index-dir /tmp/my-awi-index mcp \
  --audit-log /shared/awi/runtime/calls.jsonl
```

Память использует отдельный индекс Tantivy и ищется только при запросе `--kind agent_memory`, поэтому добавление памяти не может изменить обычное ранжирование кода/данных. Поиск MCP использует компактную форму `compact_v3` с предварительным просмотром в 1 000 символов, стабильным `file_id`, `search_id` в области запроса и метаданными определения для точных совпадений символов. По умолчанию возвращается 5 результатов, а запросы свыше 20 сжимаются до 20. Передайте возвращённый `search_id` и необязательный точный `symbol` в `workspace_inspect`, чтобы связать проверку с её поиском и центрировать выдержку на определении. Начните с одного запроса, богатого идентификаторами, вместо параллельных поисков по синонимам, и расширяйте только тогда, когда первый набор результатов лишён доказательств. Когда точный путь уже известен, читайте его напрямую с помощью инструментов файлов хоста. Фрагменты поиска генерируются из ограниченных сохранённых окон исходного кода, а лёгкое переранжирование разнообразия каталогов предотвращает заполнение набора результатов одной папкой артефактов. Сервер stdio поддерживает стандартный устаревший `ping` MCP и ограничивает согласование на основе инициализации протоколом `2025-11-25`.

### Семантический поиск

AWI может добавить семантическую полосу Harrier GGUF Q8 без изменения интерфейса инструментов MCP. Встраивания документов вычисляются во время `reconcile`, `notify` или начального `semantic-build`; обычные поиски вычисляют только встраивание запроса. SQLite остаётся авторитетным, а семантические кандидаты, чьё поколение файлов не актуально, отбрасываются.

Создайте выделенную среду Python и включите сайдкар:

```bash
python3 -m venv ~/.cache/awi/semantic-venv
~/.cache/awi/semantic-venv/bin/pip install -r requirements-semantic.txt

export AWI_SEMANTIC_MODEL=/path/to/harrier-oss-v1-270M-Q8_0.gguf
export AWI_SEMANTIC_MODEL_SHA256=fe12f3583dbbb832def4cffeb46c0d0ab49a3288542d5cdbaeb1741315a01b87
export AWI_SEMANTIC_PYTHON="$HOME/.cache/awi/semantic-venv/bin/python"
export AWI_SEMANTIC_THREADS=16
export AWI_SEMANTIC_EMBED_WORKERS=1
```

Для существующего каталога предварительно вычислите каждый подходящий файл один раз:

```bash
awi --index-dir /tmp/awi-writer semantic-build \
  --publish-dir /shared/awi-publication --json
```

Прерванная массовая сборка может повторно использовать полные поколения файлов, уже зафиксированные в LanceDB. Если содержимое рабочей области изменилось во время неудачной попытки, сначала согласуйте каталог без публикации, затем возобновите:

```bash
env -u AWI_SEMANTIC_MODEL \
  awi --index-dir /tmp/awi-writer reconcile /path/to/workspace --json
awi --index-dir /tmp/awi-writer semantic-build --resume \
  --publish-dir /shared/awi-publication --json
```

Режим возобновления по-прежнему перехеширует каждый источник по SQLite и повторно использует только точные пары `(file_id, generation)`. Запечатывание выполняет ту же полную проверку покрытия и отсекает устаревшие пары перед публикацией.

Сборка использует чанки, учитывающие токенизатор и структуру, ограниченные 480 токенами модели, сохраняет не более четырёх чанков на файл, применяет инструкцию запроса Harrier только к запросам и L2-нормализует встраивания. Исходный код, текст, полуструктурированное и табличное содержимое подходят; конфиденциальные или только метаданные файлы и память агента исключены. Ненулевой подходящий файл, чья извлечённая полезная нагрузка пуста, получает вектор заголовка пути и типа, поэтому покрытие сборки и публикации остаётся идентичным; нулевые байтовые файлы остаются исключёнными.

Массовые сборщики могут установить `AWI_SEMANTIC_EMBED_WORKERS` больше единицы. Дополнительные экземпляры модели GGUF загружаются лениво только для встраивания документов; обслуживание запросов сохраняет одну модель. AWI делит `AWI_SEMANTIC_THREADS` между этими рабочими, поэтому установите его на общую квоту ЦП, доступную сайдкару.

Последующие циклы производителя обновляют только изменённые файлы. Цикл без изменений проверяет покрытие и продвигает только локальный семантический манифест; он не публикует избыточный снимок NFS. Перед публикацией AWI требует покрытия LanceDB для каждой текущей подходящей пары `(file_id, generation)`. Семантическая база данных и её манифест копируются в тот же неизменяемый снимок, что и SQLite и Tantivy. Читатели отклоняют несоответствующее поколение и возвращаются к лексическому поиску, когда сайдкар недоступен. Отмените установку `AWI_SEMANTIC_MODEL`, чтобы отключить семантическую полосу.

Семантический поиск во время запроса выполняется одновременно с лексическими полосами. Векторный избыточный захват ограничен настроенным максимальным количеством чанков на файл, сохраняя покрытие Top-K на уровне файлов без возврата избыточных кандидатов чанков. Постоянные читатели выполняют один полный гибридный разогрев перед обслуживанием запросов. Сайдкар использует сигнал смерти родителя Linux, поэтому остановка читателя также освобождает модель.

Запечатанные поколения используют индекс IVF_FLAT и проверяют каждый раздел. Это сохраняет исходные нормализованные векторы Q8 и точный порядок Top-K, избегая при этом потери полноты произведения квантования при текущем размере корпуса AWI.

Для рабочих областей, поддерживаемых NFS, создавайте изменяемые индексы в локальном хранилище и публикуйте неизменяемые снимки:

```bash
awi --index-dir /tmp/my-awi-index reconcile /path/to/workspace \
  --publish-dir /shared/awi-publication --json

awi --index-dir /tmp/awi-reader serve \
  --snapshot-source /shared/awi-publication
```

Когда клиентскому хосту не хватает квоты ЦП для целей задержки GGUF, запустите читатель снимков на рабочем процессе ЦП и сохраните локальный сокет MCP с туннелем stream-local с повторным подключением:

```bash
scripts/remote-reader-tunnel.sh \
  /tmp/local-awi.sock /tmp/remote-awi.sock <worker-ip> <ssh-port>
```

### Цепочка автоматического обновления

Чтобы поддерживать общую публикацию актуальной без ручных согласований, запустите постоянного производителя рядом с читателем. Производитель согласует корни и публикует новый неизменяемый снимок только при изменении содержимого; читатель, следующий за снимком, атомарно переключается на каждое новое поколение при своём следующем запросе. Это замыкает цикл от начала до конца: отредактируйте файл, и читатель автоматически отразит его.

Загрузка снимка и проверка контрольной суммы выполняются в фоновом рабочем процессе обновления. Запросы продолжаются к последнему действительному поколению, пока материализуется новый снимок, избегая пауз обновления NFS на пути запроса. Отключение отдельного клиента или сбой записи регистрируется без завершения работы общего демона.

Локальные дисковые корни отслеживаются в реальном времени (inotify), поэтому изменения публикуются в пределах окна устранения дребезга. Удалённые корни (NFS и аналогичные, обнаруженные через `/proc/mounts`) и периодический тик безопасности каждые `--interval-ms` управляют остальным, потому что события файловой системы ненадёжны для удалённых записей. Если наблюдатель не может запуститься, производитель чисто деградирует до чистого периодического согласования. События доступа и только метаданных игнорируются, чтобы предотвратить самозапускающиеся сканирования; обновления `.log`, `.jsonl`, `.ndjson`, `.csv`, `.tsv` и `.parquet` с интенсивным добавлением откладываются до периодического прохода вместо перестроения снимка для каждой записи. Каждый цикл также заново обнаруживает источники для проектов, зарегистрированных `awi memory`. Новые корни памяти агентов индексируются автоматически, а исчезнувшие зарегистрированные корни согласуются, поэтому удалённые доказательства не обслуживаются.

```bash
# Производитель: наблюдать за локальными корнями в реальном времени, согласовывать каждый корень не чаще, чем каждые 5 с,
# объединять всплески изменений в течение 500 мс, автоматически публиковать при изменении, сохранять 3 поколения.
awi --index-dir /tmp/awi-writer watch \
  --publish-dir /shared/awi-publication \
  --interval-ms 5000 --debounce-ms 500 --retain 3

# Читатель: следовать за публикацией и автоматически активировать новые поколения.
awi --index-dir /tmp/awi-reader serve \
  --snapshot-source /shared/awi-publication
```

`watch` по умолчанию использует зарегистрированные корни без памяти; зарегистрированные проекты памяти заново обнаруживаются отдельно в каждом цикле. Передайте `--root <path>` один или несколько раз, чтобы ограничить набор. Обрезка удержания удаляет старые поколения после каждой публикации и никогда не удаляет поколение, на которое в данный момент ссылается указатель, поэтому общий каталог не может расти безгранично.

Для Codex `scripts/awi-mcp-snapshot-wrapper.sh` запускает или повторно использует один локальный демон снимков перед запуском адаптера stdio. Настройте `AWI_SNAPSHOT_SOURCE` и `AWI_MCP_AUDIT_LOG`, затем зарегистрируйте обёртку как глобальный сервер MCP. Изменяемые данные снимков остаются в `AWI_RUNTIME_DIR`, в то время как сокет Unix и блокировка запуска по умолчанию находятся в `~/.local/state/awi-$UID`, поэтому очистка временных кэшей не может отсоединить живой управляющий сокет. Холодная материализация ждёт до 10 минут по умолчанию; переопределите её с помощью `AWI_START_TIMEOUT_MS`.

### Интеграция агента одной командой

`awi integrate` обнаруживает установленные клиенты агентов и регистрирует AWI у каждого поддерживаемого хоста MCP за один проход:

```bash
# Предварительный просмотр без изменения конфигурации.
awi integrate --project-root /path/to/workspace --dry-run --json

# Настроить каждый обнаруженный поддерживаемый клиент.
awi integrate --project-root /path/to/workspace

# Ограничить операцию выбранными клиентами.
awi integrate --client codex,gemini,opencode,qwen,cline,zed,amazon-q,crush \
  --project-root /path/to/workspace
```

Команда идемпотентна и сообщает один статус на клиента: `configured`, `already_configured`, `would_configure`, `needs_attention`, `not_installed`, `unsupported` или `failed`. Метод регистрации или цель конфигурации для каждого поддерживаемого клиента:

| Клиент | Метод регистрации или цель |
|---|---|
| Codex | Официальный CLI `codex mcp add`; сохраняется в `~/.codex/config.toml` |
| Gemini CLI | Официальный CLI `gemini mcp add --scope user`; сохраняется в `~/.gemini/settings.json` |
| Claude Code | Официальный CLI `claude mcp add --scope user`; сохраняется в `~/.claude.json` |
| [GitHub Copilot CLI](https://docs.github.com/en/copilot/how-tos/copilot-cli/customize-copilot/add-mcp-servers) | `~/.copilot/mcp-config.json` |

Плагины — это необязательная упаковка для клиентов с нативной поддержкой MCP. Pi — исключение: его ядро намеренно опускает MCP, поэтому требуется расширение. Новые сеансы автоматически загружают сгенерированные записи пользовательского уровня. MCP на уровне проекта TraeCode должен быть включён один раз в настройках. Рабочие области Gemini, помеченные как ненадёжные, сообщаются как `needs_attention`, потому что Gemini подавляет все серверы MCP, пока пользователь явно не доверит рабочую область.

По умолчанию AWI регистрирует текущий двоичный файл как `awi --index-dir <absolute-path> mcp`, который является самодостаточным для локального изменяемого индекса. Производственные развёртывания на основе снимков должны явно выбрать свою обёртку с помощью `--server-command`; для пользовательских запускателей доступны повторяющиеся параметры `--server-arg`.

## Безопасность

`workspace_query` принимает только один оператор `SELECT` или `WITH` только для чтения по явным входным данным под зарегистрированными корнями. Он применяет ограничения по времени ожидания, строкам и выходным байтам, отключая загрузку расширений DuckDB и внешний доступ.

Ответы на поиск и проверку ограничены. Обнаружение знаний агентов ограничено родительскими файлами `AGENTS.md` и манифестами `SKILL.md` в известных каталогах для каждого клиента. Обнаружение памяти ограничено курируемыми файлами, сопоставленными с выбранным проектом; необработанные истории требуют явного согласия. AWI никогда не индексирует весь домашний каталог. Конфиденциальные файлы, сгенерированные каталоги, негабаритное содержимое и побеги символических ссылок исключены по умолчанию. Исключённые по умолчанию каталоги: `.git`, `.hg`, `.svn`, `.awi-index`, `node_modules`, `target`, `__pycache__`, `.pytest_cache`, `.mypy_cache`, `.ruff_cache`, `.ipynb_checkpoints`, `.venv`, `.idea`, `.vscode` и `.cache`, плюс созданные агентом `.codex-work` и `.worktrees`, наряду с правилами `.gitignore` и `.awiignore`. Производитель `watch` применяет те же исключения к событиям файловой системы, поэтому изменение в этих каталогах никогда не пробуждает согласование. Фильтры корня поиска принимают либо индексированный корень, либо существующую родительскую область, содержащую индексированные корни. Корни структурированных запросов остаются точными записями списка разрешений.

Ведение журнала аудита MCP необязательно. При включении AWI записывает частные (`0600`) записи JSONL, содержащие ограниченные и отредактированные учётные данные аргументов, процесс вызывающего, стандартизированное имя клиента, необязательный идентификатор сеанса, маркер синтетического вызова, продолжительность, результат, детали ошибки, байты ответа, байты текстовой/структурированной полезной нагрузки, количество попаданий/строк, а также отдельные флаги усечения предварительного просмотра и сжатия ограничений. Схема v5 сохраняет поля связи поиска/проверки v4 и добавляет `client_name`, `session_id` и `synthetic`. Установите явные метаданные с помощью `AWI_MCP_CLIENT_NAME`, `AWI_MCP_SESSION_ID` и `AWI_MCP_SYNTHETIC`; инициализация MCP `clientInfo.name` переопределяет вывод процесса. Активный журнал ротируется при 64 МиБ и сохраняет один предыдущий файл. Отчёты о принятии проекта используют [`eligible_session_adoption`](session-adoption.md), а не все сеансы проекта в качестве знаменателя.
