## Использование

```bash
# Только курированная память и сводки.
awi --index-dir /tmp/my-awi-index memory \
  --project-root /absolute/path/to/workspace

# Явно включить соответствующую необработанную историю чатов/сеансов.
awi --index-dir /tmp/my-awi-index memory \
  --project-root /absolute/path/to/workspace \
  --include-raw

# Искать только память, связанную с текущим проектом.
awi --index-dir /tmp/my-awi-index search "previous deployment decision" \
  --kind agent_memory \
  --context-path /absolute/path/to/workspace \
  --json
```

Установщик по умолчанию запускает курированную форму. Используйте `--skip-agent-memory`, чтобы отключить её, или `--include-raw-memory`, чтобы выбрать необработанную историю.

## Источники

Обнаружение ограничено выбранным каноническим проектом:

| Агент | Источники курированной памяти по умолчанию | Дополнительная необработанная история |
|---|---|---|
| Trae | профиль пользователя, подходящая память проекта, краткие содержания тем, краткие содержания сеансов | ничего, кроме этих сводок |
| Codex | `MEMORY.md`, `memory_summary.md`, подходящие сводки развёртывания | связанные необработанные JSONL развёртывания и `raw_memories.md` |
| Zcode | корень памяти, сопоставленный с проектом через метаданные среды выполнения Zcode | подходящие файлы развёртывания/агента |
| Gemini CLI | нет | сопоставленные история проекта и каталоги чатов |
| Claude Code | подходящий каталог памяти проекта | файлы сеансов, идентифицирующие проект |

Каталоги сеансов Argos/SRE намеренно исключены, поскольку они требуют диагностического рабочего процесса Argos, а не массовой индексации файлов. AWI никогда не сканирует весь домашний каталог.

## Метаданные и ранжирование

Каждое совпадение памяти включает:

- исходного агента;
- слой: `user_profile`, `project_summary`, `topic_summary`, `session_summary`, `memory_note` или `raw_history`;
- необязательные `name` и `description` YAML frontmatter;
- канонический корень рабочей области и ключ проекта поставщика, когда они доступны;
- идентификатор сеанса, когда он может быть получен;
- время наблюдения и флаг необработанной истории.

Когда предоставляется `context_path` или фильтр корня проекта, память из другого проекта отклоняется. Память точного проекта ранжируется выше глобальной памяти. Точные совпадения имени файла и `name` frontmatter получают самый сильный метаданный буст; перекрытие описаний даёт меньший буст. Запросы в форме идентификаторов понижают широкие сводки `MEMORY.md`/проекта, если только сама сводка не совпадает точно с сущностью. Обычный порядок слоёв остаётся неизменным для широких запросов, курированные сводки ранжируются выше необработанной истории, а недавность — лишь небольшой тай-брейк. Копии с идентичным содержимым из разных агентов сворачиваются после ранжирования. Если фильтр типов не задан, память участвует в поиске по умолчанию. `--kind agent_memory` используется только для сужения результатов до памяти. Документы памяти используют выделенный индекс Tantivy, поэтому их словарь не может изменить обычные IDF-статистики или ранжирование кода/данных.

## Разбор и безопасность

Markdown-память индексируется как ограниченный текст. JSON/JSONL-память нормализуется к человеко-значимым полям, таким как намерение, действия, результат, извлечённые факты, роль, сообщение и содержимое; транспортные идентификаторы и внутренняя дайджест-метаданные опускаются из поискового документа. Память JSONL не отправляется в профилирование DuckDB.

Обычные проверки размера, UTF-8, игнорирования и конфиденциальных имён файлов по-прежнему применяются. Данные учётных записей или закрытые ключи с высокой уверенностью делают весь файл памяти метаданными. Необработанная история отключена, если явно не запрошена, и негабаритные необработанные файлы остаются метаданными в рамках настроенного лимита содержимого.

`awi memory` сохраняет канонический корень проекта и политику необработанной истории. Каждый цикл производителя переоткрывает источники агентов этого проекта перед публикацией, поэтому новые каталоги проектов поставщика появляются без переустановки AWI. Ранее зарегистрированные корни также согласовываются, когда они исчезают, предотвращая возможность поиска удалённой памяти. Дополняемый JSONL сводок обновляется при следующей периодической сверке; дополняемые с высокой частотой необработанные файлы не вызывают перестроения снимков при каждой записи.

`awi status --json` раскрывает объект `memory` с количеством зарегистрированных проектов/источников, активными файлами, новейшим поколением памяти и относительным отставанием поколений, файловой системой `stale_files`/`missing_files`, максимальным отставанием источников и возрастом самого старого источника. Показатели устаревших и отсутствующих файлов файловой системы являются авторитетными сигналами свежести; лишь небольшое отставание поколений само по себе не доказывает актуальность внешней памяти.

## Проверка разработки

Изолированный запуск Bona обнаружил 35 корней, относящихся к проекту, и проиндексировал 489 курированных файлов из Codex, Trae и Zcode с нулевыми ошибками извлечения; необработанные чаты Gemini остались исключёнными. Существующий набор из 16 случаев поиска кода/данных оставался бит-в-бит стабильным: Recall@10 `1.0`, MRR `0.6006`, nDCG@10 `0.6950` и показатель устаревания `0`. P95 сборки релиза составлял `24.06 мс`. Этот набор всё ещё `candidate_pending_dual_review`, не замороженный ворота релиза. Не сообщайте о формальной точности/полноте, Inspect@K или MRR, пока два разных рецензента не разметят независимо набор запросов и не уладят разногласия.
